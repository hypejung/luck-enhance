# 운빨강화하기 — 작업 맥락 (새 세션은 이것부터 읽는다)

다른 세션이 처음부터 같은 맥락으로 일할 수 있게 지금까지의 구조·규칙·결정을 모은 문서다.
코드 위치는 줄 번호 대신 **함수·상수 이름과 섹션 주석**(`// ---------- 이름 ----------`)으로 적는다 — 줄 번호는 금방 바뀐다.
큰 결정을 하거나 새 시스템을 넣으면 이 문서도 같이 갱신한다.

## 2. 사용자 작업 규칙 (꼭 지킨다)
- 반영: `CLAUDE.md` 그대로. 사용자가 **"반영해줘"** → 수정·커밋·push·PR까지 한 번에. 불명확하면 diff를 보여주고 먼저 묻는다.
- 평소 흐름: 작업 브랜치에 커밋·push → **"main에 merge해도 될까?"** 라고 묻고, 허락(또는 "merge ㄱㄱ")을 받으면 merge한다.
  "merge ㄱㄱ 패치노트는 ㄴㄴ"처럼 오면 merge만 하고 패치노트는 쓰지 않는다.
- 설계: 새 컨텐츠나 밸런스 변경은 **표로 먼저 보여주고 컨펌받은 뒤 구현**한다(`luck-enhance-design-review` 스킬).
  사용자가 "ㄱㄱ", "그대로 ㄱㄱ", "A로 가"라고 하면 그 안대로 구현한다.
- 패치노트: 사용자가 "패치노트로 남겨"라고 한 것만 쓴다. 형식·만료·버전 규칙은 `CLAUDE.md`.
- **비밀값**: 개발자 비밀번호·동기화 비밀번호·토큰을 채팅에 붙여 달라고 하지 않는다. 코드·저장소에 비밀번호를 넣지 않는다(해시만).
- 사용자가 직접 거절한 것: 레이드 순위 조작 방지("양심 문제") — 넣지 않는다.

## 3. 빌드·배포·merge
```bash
# 빌드 + 확인 (-n 필수: 없으면 내용이 같아도 해시가 매번 바뀐다)
gzip -9 -n -c game-source.html > index.html.gz && gunzip -c index.html.gz | diff -q - game-source.html
git add game-source.html index.html.gz && git commit -m "..."
for i in 2 4 8 16; do git push -q -u origin <작업 브랜치> && break; sleep $i; done
# merge (허락 받은 뒤)
git fetch origin main && git checkout main && git merge --ff-only origin/main && git merge --no-edit <작업 브랜치> \
  && git push origin main && git checkout <작업 브랜치>
```
- 커밋 메시지는 한국어 한 줄 요약 + 필요하면 본문. 모델 이름은 넣지 않는다.
- 세이브 구조를 바꾸면 `init()`/`load()`의 이전 버전 호환(마이그레이션) 부분을 같이 고친다. 기존 세이브를 깨면 안 된다.

## 4. 테스트 (`tools/test/`)
- 준비: 저장소 루트에서 `python3 -m http.server 8974`. Playwright와 Chromium은 클라우드 컨테이너에 설치돼 있다(`tools/test/env.js`).
- Firebase(동기화 서버)는 컨테이너에서 접속이 막혀 있어서, 스크립트가 빈 응답(`null`)으로 대신한다.
- 게임 코드는 즉시실행함수 안에 있어서 콘솔에서 바로 접근할 수 없다. 개발자 통로를 쓴다:
  `await __dev(비밀번호)` → 성공하면 `__devEval(코드)`로 게임 내부에서 실행. 코드에는 비밀번호의 SHA-256(`DEV_PASS_HASH`)만 있다.
- 비밀번호는 **환경 변수 `LUCK_DEV_PASS`** 로 넣는다(클라우드 환경 설정의 환경 변수). 없으면 `tools/test/.devpass`(git 무시) 파일을 쓴다.
  비밀번호를 모르면 사용자에게 환경 변수 설정을 부탁한다 — 채팅으로 받지 않는다.
- 스크립트
  | 파일 | 용도 |
  |---|---|
  | `smoke.js` | 모든 탭 열기 + 사냥 틱 300회 → 페이지 오류 확인. 변경마다 돌린다 |
  | `devlib.js` | `unlock(page)`, `run(page, fn, arg)` — 게임 내부 실행 도우미 |
  | `sim_lib.js` | 측정용 표준 세팅(카마소츠 +30, 훈련 40, 보스 장신구 전부, 신화 +27 보조무기 등) |
  | `measure-ancient-glove.js` / `measure-genesis-glove.js` | 장갑 측정(아래 5절 방법) |
- 오래 걸리는 측정은 `setsid nohup node ... > out.txt &`로 돌리고, 끝났는지는 `pgrep -f "[n]ode measure"`로 본다
  (대괄호를 넣어야 pgrep 명령 자기 자신이 걸리지 않는다).
- 전투를 빠르게 돌릴 때: `Date.now`를 가짜 시계로 바꾸고(`sim_lib.setup`) `tick(0.1)`을 반복 호출한다. `Math.random`은 시드 고정 함수로 바꾼다.

## 5. 게임 구조
### 월드와 장비 축
| 월드 | 층 | 이름 | 그 월드에 새로 붙는 장비 | 해금 |
|---|---|---|---|---|
| 1 | 1~20 | 푸른세계 | 무기(메인), 장신구, 룬 | 시작 |
| 2 | 21~40 | 황혼국 | 보조무기 | 토벌전 `WORLD2_RAID_UNLOCK_STAGE`(9)단계 |
| 3 | 41~60 | 🌌 성야국 | 장갑(의복) | 토벌전 `WORLD3_RAID_UNLOCK_STAGE`(25)단계 |
- 층 데이터: `FLOORS`(이름·몬스터·체력·재료·보스·방해 패턴). 골드: `floorGold(f)`(월드2부터는 HP 비례).
- 사냥 → 처치(`handleKill`) → 드롭(`dropRoll`: 골드·랜덤박스·무기·재료). 층마다 보스(`BOSS`: 체력 ×100, 60초, 쿨타임 1시간).

### 등급 (`GRADES`, 0~7)
일반 · 레어 · 에픽 · 유니크 · 레전더리 · 신화 · **고대(6)** · **태초(7)**.
- 고대: 보스 드롭 전용. 판매 불가, 고유 효과가 있다. 무기의 고대 효과는 `ANCIENT_SPIRITS`(에이션트 스피릿)라고 부른다.
- 태초: 층마다 1개씩 있는 초저확률 고유 아이템. 판매 불가, 파괴 없음.
  - 무기 = `GENESIS_ARTIFACTS`(태초의 유물, 고유스킬)
  - 보조무기 = 태초 보조무기
  - 장갑 = `GLOVE_GENESES`
  - 누가 얻으면 모든 유저에게 배너로 알린다(`genesisFeed`).

### 강화
- 무기 +30: `ENH` 표를 쓴다.
  - 성공 확률: `gradeAdjustedSuccess`(+15부터 등급 페널티)
  - 파괴 확률: `effectiveDestroyChance`(+10~19는 표의 1/4, +20(8%)부터 +29(30%)까지 선형)
  - 실패 중 하락/유지는 35/65(`ENH_DOWN_BASE`). 태초는 파괴 대신 하락만 있다.
- 공격력 배율 `enhAtkMult`: +10까지는 선형, 그 뒤로는 가속형. 비용은 `등급 기본비용 × 1.4^단계`.
- 고대·태초 강화에는 무기의 정수(`weaponEssence`)도 든다.
- 보조무기·장갑도 같은 구조다(각자 표와 재료가 있음).
- 강화데이 이벤트(`ENHANCE_EVENT`, 수·일요일): 파괴 확률 절반, 비용 할인.

### 코드 지도 (자주 보는 곳)
- 상태:
  - `let S`(세이브 상태), `newState()`(필드 설명 주석이 붙어 있음)
  - `init()`(로드·마이그레이션)
  - `save()`/`load()`(`SAVE_KEY = 'luckEnhance_v1'`, 서명·백업 포함)
- 큰 수: `BN`(가수×10^지수). 골드·체력은 BN이고, 일반 계산은 Number다.
- 전투:
  - 매 틱 `tick(dt)` → 공격 → `dealMonDamage`
  - 처치 `handleKill`
  - 전투 상태 `bossFight`(`isRaid`/`isLibrary`/펀치 등), 방해 엔진 상태 `bd`
- 시작 함수: `startBossFight` · `startRaidFight` · `startLibraryFight` · `startPunchFight`.
  **전투 단위 스택은 `resetTimedStacks()`(전투 시작)와 `spawnMonster()`(일반 사냥 대상 교체) 양쪽에서 초기화한다.**
- 능력치: `weaponAtk`, `weaponSpeed`, `accEff()`(장신구·컬렉션 등 합계), `awakenStat`, `typeTrait`.
- 장비 효과 묶음(섹션 주석): "고대 보조무기 전투 효과", "태초 보조무기 전투 효과", "🏺 고대 장갑 전투 효과", "🌟 태초 장갑 전투 효과", "OOO(태초 무기) 전용 전투 효과".

## 6. 밸런스 기준과 측정
- 기준은 "같은 종류 **신화 +27** 대비 몇 배의 화력이 되는가"로 잰다. 측정 결과는 해당 `design-notes`에 남긴다.
  | 대상 | 목표 |
  |---|---|
  | 고대 보조무기·고대 장갑 | ×1.6 |
  | 태초 보조무기·태초 장갑 | ×2.5 |
  | 고대 무기(스피릿) | `luck-enhance-ancient-weapon-balance` 스킬(펀치기계 인덱스 90~110%) |
  | 태초 유물(무기) | `luck-enhance-genesis-artifact-design` 스킬(고대보다 확실히 강하게, 유틸형은 전투력을 낮게) |
- 장갑 측정법(`measure-*-glove.js`):
  - 싸움 세 가지: 그 장갑 층의 보스, 토벌전 35단계, 도서관 30서고.
  - 보스 체력을 1/M로 줄여 가며 11번 이분 탐색하고, 시드를 고정해 3판 중 2판을 이기는 M을 찾는다.
  - (신화 +27 장갑의 M) ÷ (대상 장갑의 M)을 세 싸움에 대해 기하평균한다.
  - 도서관 30서고의 저주는 주마다 바뀌어서, 도서관 수치는 측정한 주에 따라 달라진다.
    예: 2026-10-16 재측정 때 41~43층 도서관 수치가 기록보다 0.3~0.8 높게 나왔다. 그 층 보스와 토벌전 수치는 기록과 같았다.
- 장비 각인 비용 배수 규칙: `CLAUDE.md` "장비 추가 규칙".
- 스킬 3개(설계 절차): `luck-enhance-design-review`(일반 설계: 표 → 컨펌 → 구현), 고대 무기 밸런스, 태초 유물 설계.
  배포 절차 스킬 `luck-enhance-deploy`는 사용자 계정 쪽에 있다.

## 8. 태초 장갑 공통 규칙 (최근 작업이라 요약)
- 정의 `GLOVE_GENESES`(층별, 아직 없는 층은 null).
- 드롭 `rollGenesisGlove`: 사냥 정예 ×5, 보스 ×10, 세트 ×3. 같은 층의 태초 장갑은 중복으로 나오지 않는다.
- 강화: 파괴 없음, 정수 성장 ×1.35.
- 효과:
  - 패시브는 봉인 중에 멈춘다(`gloveGenesisPassive`).
  - 반격은 패턴이 오는 순간 항상 터진다(`gloveGenesisOnPattern`). 패턴이 12초 동안 없으면 온 것으로 친다(`GLOVE_GENESIS_FAKE_EVERY`).
  - 전투 상태는 `fx.ggl`이고, `fx.agl`과 같은 곳에서 초기화한다.
- 수치와 측정 결과는 `design-notes/ancient-genesis-gloves.md`에 있다.
