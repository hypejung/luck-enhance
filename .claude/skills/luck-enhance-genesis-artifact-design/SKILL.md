# 태초의 유물(Genesis Artifact) 설계 워크플로우

`GENESIS_ARTIFACTS`(각 사냥터당 1개, 총 20개, 등급의 최상위)를 새로 채우거나 다시 설계할 때는
아래 단계를 순서대로 밟는다. 카마족의 조종(동굴/야생 박쥐, floor 1) 설계 세션에서 확정된 절차다.
**1~4단계까지는 `Edit`/`Write`로 `game-source.html`을 건드리지 않는다** — `luck-enhance-design-review`의
"표로 먼저 보여주고 컨펌받기" 원칙을 이 컨텐츠 타입에 맞게 구체화한 것이다.

## 0. 리서치

- 대상 사냥터의 몬스터/테마를 `FLOORS`에서 확인한다.
- 이미 채워진 `GENESIS_ARTIFACTS` 항목(들)을 읽고 톤·구조를 파악한다 — 특히 `글러트니의 목걸이`
  (floor 0)와 `카마족의 조종`(floor 1)이 기준 예시다: 이름/부제/아이콘/로어(짧은 시적 산문, 마지막에
  존재의 이름을 영어 병기로 reveal)/효과 2개/`uniqueSkill` 구조를 그대로 따른다.
- 무기 타입(`type: 'weapon'`)이지만 실제 형태는 목걸이·종 같은 유물/성물이어도 된다 — 이미
  확립된 자유도다.

## 1. 컨셉 초안 2~3개를 표로 제시

몬스터 테마에서 뽑을 수 있는 메커니즘 컨셉(예: 박쥐 → 초음파/메아리/무리/야행성 등) 중 서로
겹치지 않는 2~3개를 뽑아, 이름(가칭)·아이콘(가칭)·핵심 컨셉 한 줄·효과 2개(간단 버전)로 표를
만들어 제시한다. 이 단계에서는 아직 정식 로어나 신화 레퍼런스를 붙이지 않아도 된다 — 사용자가
방향(또는 여러 컨셉의 조합)을 고르게 하는 게 목적.

## 2. 신화/서사 레퍼런스 확정

사용자가 컨셉 방향을 고르면, **그 컨셉에 실제로 들어맞는 신화·전설·고전 속 존재**를 찾아
이름과 서사의 뼈대로 삼는다(글러트니=칠죄종, 카마족=포폴 부의 박쥐 신 같은 방식). 지어낸
가상의 이름보다 실재하는 신화적 레퍼런스를 우선한다 — 서사에 진짜 무게가 실린다. 후보가
애매하면 2개 정도 제시하고 사용자에게 확인받는다.

## 3. 효과를 "고대보다 확실히 강하게" 재설계

태초는 게임의 최종 등급이다. 초안 단계에서 잡은 효과가 약해 보이면(사용자가 "약한 것 같다"고
하지 않아도, 고대 스피릿 수준과 비슷하거나 그 이하로 보이면 먼저) 아래 절차로 다시 잡는다.

1. `luck-enhance-ancient-weapon-balance` 스킬을 불러와 고대 등급의 기준(펀치기계 측정 방법론,
   90~110% 인덱스 목표)을 확인한다.
2. 그 기준을 명확히, 크게 상회하는 것을 목표로 잡는다(고대와 "비슷한 수준"이 아니라 "고대 바로
   위 최종 등급"이라는 체감이 나야 한다). 절대 수치보다 **비율/구조**로 설계한다 — 예: 확정형
   곱연산 증폭(치명타/연타 판정과 무관하게 항상 발동), 주기적 처치/burst형 등 고대에 없던 강도의
   메커니즘을 적극적으로 쓴다.
3. 창의성도 함께 요구된다 — 기존 고대 스피릿·룬 특수효과와 트리거 조건이 겹치지 않는지 확인하고,
   겹치면 다르게 비튼다(예: "즉사 실행"은 보스 밸런스를 깨므로 보스전에서는 고정 데미지 폭발로
   대체하는 식의 분기).
4. 정확한 최종 숫자는 이 단계에서 확정하지 않아도 된다 — "1차 초안이며 구현 후 펀치기계
   측정으로 조정한다"고 명시하고 사용자 컨펌을 받으면 된다(진짜 측정치는 4단계 구현 이후에나
   나온다).
5. **유틸형 효과(전투와 무관한 파밍/재도전 횟수/자원 등)가 하나라도 섞여 있으면, 전투력(펀치기계
   DPS 인덱스)은 카마소츠처럼 "전투 효과만 있는" 태초보다 확실히 낮게 잡는다.** 유틸 가치와
   전투 가치를 총합으로 재조정해 인위적으로 맞추려 하지 말고, 그냥 전투 쪽 숫자를 명확히
   낮춰서 "이 태초의 핵심 가치는 전투가 아니다"가 체감되게 한다(레드캡=파밍 잭팟, 오시리우스=
   재도전 빈도 상승, 둘 다 이 원칙으로 카마소츠 대비 10~20%대 DPS로 낮춰 잡았다). 몇 %까지
   낮출지는 사용자에게 확인하되, "확실히 약하게"라는 방향 자체는 되묻지 않고 기본으로 적용한다.

## 4. 확정 표 제시 → 컨펌 대기

이름/부제/아이콘/로어(전문)/효과 2개(수치 포함, 1차 초안 명시)를 표+로어 형태로 다시 제시하고
컨펌을 기다린다. 일부만 수정 요청이 오면 그 부분만 고쳐서 다시 보여준다.

## 5. `effectsText`는 끝까지 추상적으로 쓴다

플레이어에게 보이는 `effectsText` 두 줄은 **정확한 수치나 정확한 발동 조건(예: "15번째",
"80%")을 절대 노출하지 않는다.** 시적이고 분위기 있는 한 줄로, 무엇이 일어나는지 암시만 한다.
"몇 번이고", "N번째" 같이 횟수를 짐작하게 하는 표현도 피한다 — 실제 수치는 코드 주석과
`CAMAZOTZ` 같은 상수 객체에만 존재하고, 플레이어가 보는 텍스트는 순수 분위기여야 한다.

- 나쁜 예: `'천 개의 메아리: 모든 타격은 어둠 속에서 몇 번이고 되돌아온다.'` (횟수를 암시)
- 나쁜 예: `'공진 파쇄: 열다섯 번째 울림에, 그 무엇도 온전할 수 없다.'` (정확한 횟수 노출)
- 좋은 예: `'천 개의 메아리: 하나의 타격은 소리가 되어, 스스로 되돌아와 다시 적을 친다.'`
- 좋은 예: `'공진 파쇄: 쌓여만 가던 울림은, 어느 순간 모든 것을 무너뜨린다.'`

## 6. 컨펌 후 구현

`game-source.html` 반영 순서:

1. `GENESIS_ARTIFACTS` 배열의 해당 `floor` 인덱스 `null`을 정식 항목으로 교체(다른 `null` 개수가
   안 맞지 않도록 주의).
2. 글러트니/카마족처럼 "OOO(태초 무기) 전용 전투 효과" 주석 블록 아래에 상수 객체 + 훅 함수를
   추가한다(예: `CAMAZOTZ`, `camazotzEcho()`, `camazotzResonance()`).
3. `attack()` 함수 안, 주 타격(`mon.hp -= dmg`)이 끝나는 지점 근처에 훅 함수 호출을 추가한다.
   `hasGenesisEquipped('아이디')`로 장착 여부를 판정한다.
4. 전투 단위로 리셋되어야 하는 스택이 있으면 `spawnMonster()`(일반 사냥 대상 전환)와
   `resetTimedStacks()`(보스전/토벌전/도서관/펀치기계 시작) **양쪽 다** 리셋 코드를 추가한다
   (`luck-enhance-ancient-weapon-balance`의 "전투 단위 스택 원칙"과 동일).
5. `effectsText`/로어 렌더링은 `GENESIS_ARTIFACTS.find(a => a.id === w.genesisId)` 기반으로 이미
   완전히 데이터 주도이므로, 인벤토리/강화기/도감 쪽에 별도 UI 코드를 추가할 필요는 보통 없다.

## 7. 검증

- Playwright로 `grantGenesisArtifact()` → 장착 → `attack(w)` 직접 호출 방식으로 데미지 배수를
  검증한다(다른 확률 요소는 `Math.random`을 고정값으로 스텁해서 제거).
- 스택형 효과는 임계값 도달 시점(정확히 N번째 공격)과 대상 전환 시 리셋을 각각 테스트한다.
- 보스전/일반 사냥 분기가 있으면 `bossFight.active`를 토글해가며 양쪽을 모두 검증한다.
- 마지막으로 실제 `tick()` 루프를 몇 번 돌려 실전 경로에서 에러가 없는지 확인한다.
- 배포는 `luck-enhance-deploy` 스킬을 따른다.

## 참고

- 이 스킬은 **태초의 유물 전용**이다. 고대(6등급) 스피릿 수치는 `luck-enhance-ancient-weapon-balance`,
  그 외 일반적인 신규 컨텐츠 설계는 `luck-enhance-design-review`를 따른다.
- 이미 합의된 설계를 그대로 구현해달라는 요청이면 0~4단계를 건너뛰고 바로 6~7단계로 간다.
